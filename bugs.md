### BUG-001: Нестриминговый ответ модели падал с HTTP 502

- Серьёзность: S2
- Сценарий / случай: F21 / F21-H2 (голосовая команда), также F03 (нестриминговый путь)
- Экран: S02/S27 (свёрнутый режим)
- Сборка: локальная 2026-11-24  Браузер / устройство: Chromium (Playwright), 1600×900

Шаги
1. Поднять ядро и заглушку Ollama.
2. Свернуть окно, нажать `W` дважды — уходит команда «открой отчёт по проекту».
3. Наблюдать подпись свёрнутого режима.

Ожидание: подпись показывает ответ модели.
Факт: подпись показывала `Ядро: HTTP 502`; ответ `POST /api/messages.send` содержал `Модель недоступна: Attempted to access streaming response content, without having called 'read()'`.
Доказательство: падавший тест `F21-H2` (caption «Ядро: HTTP 502»), ручной вызов API → 502 с этим текстом.
Предполагаемая причина: в `core/streams.py` при `stream=False` вызывался `response.json()` внутри `http.stream(...)`, до `aread()`.
Статус: **исправлен** — добавлен `await response.aread()`; регрессия покрыта `test_non_streaming_chat_reads_body`, e2e `F21-H2` зелёный.

### BUG-002: Недостаточный контраст моно-меток в тёмной теме

- Серьёзность: S3
- Сценарий / случай: F04-H1 / F21-H1 (axe на всех экранах)
- Экран: S02, S03
- Сборка: локальная 2026-11-24  Браузер / устройство: Chromium (Playwright), 1600×900

Шаги
1. Открыть рабочее пространство в тёмной теме.
2. Запустить `AxeBuilder({ page }).analyze()`.

Ожидание: нарушений WCAG AA нет (в `replica/design/components.md` заявлено 0 ошибок).
Факт: `color-contrast` (serious): `kbd` и `.tool .tag` — `#6E8296` на `#111923`, соотношение 4.46:1 при требуемых 4.5:1.
Доказательство: вывод axe в проваленном `F21-H1`: `contrastRatio: 4.46`, target `kbd` и `.tool:nth-child(1) > .tag`.
Предполагаемая причина: токен `--color-text-faint` использован для мелкого текста поверх `--color-surface-2`, хотя проверка контраста в дизайне делалась для другого фона.
Статус: **исправлен** — цвет `kbd` и `.tool .tag` заменён на `--color-text-muted`; axe зелёный.

### BUG-003: Нарушения семантики и доступности оболочки

- Серьёзность: S3
- Сценарий / случай: F04-H1 / F21-H1 (axe)
- Экран: S02
- Сборка: локальная 2026-11-24  Браузер / устройство: Chromium (Playwright), 1600×900

Шаги
1. Открыть рабочее пространство, затем свёрнутый режим.
2. Запустить axe на каждом экране.

Ожидание: нет нарушений `page-has-heading-one`, `region`, `landmark-unique`, `scrollable-region-focusable`.
Факт: нет `h1`; содержимое статус-строки вне landmark; два безымянных `complementary` (`aside.sidebar`, `aside.panel`); прокручиваемый `.chat` недоступен с клавиатуры.
Доказательство: вывод axe в проваленных `F21-H1` (до исправления) и `F04-H1`.
Статус: **исправлен** — `<h1>` в шапке сцены, `role="banner"` на статус-строке, `aria-label` на обоих `aside`, `role="log"` + `tabIndex=0` на истории сообщений; axe зелёный.

### BUG-004: Время сообщений отображалось как INVALID Date

- Серьёзность: S3
- Сценарий / случай: F04-H1 (обнаружено при снятии скриншота для `/replica-diff`)
- Экран: S02
- Сборка: локальная 2026-11-24  Браузер / устройство: Chromium, 1440×900

Шаги
1. Открыть рабочее пространство с историей из SQLite.
2. Посмотреть метки времени у сообщений.

Ожидание: время отправки, например `19:32`.
Факт: у всех сообщений `INVALID Date`.
Доказательство: `clone-screens/S02_workspace.png`; `GET /api/messages.list` возвращал `2026-11-24T16:24:337490Z`.
Предполагаемая причина: в `db.now_iso()` использовался Python-формат `%f` (микросекунды) без разделителя и секунд — получилась невалидная ISO-строка, которую `new Date()` в браузере не парсит.
Статус: **исправлен** — `now_iso()` переведён на `isoformat(timespec="milliseconds")`; миграция `0003_fix_timestamps.sql` нормализует уже сохранённые записи; регрессия покрыта `test_timestamps_are_valid_iso`.
